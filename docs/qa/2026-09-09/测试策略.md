# 测试策略 — 2026-09-09

## 1. 目标与裁决

- **目标**：验证 P0 主链“准备 → 求解 → 发布 → 查询/导出”以及 P1 的协作、通知、复用、模板、复盘、问题闭环。
- **范围决策**：沿用已确认的“先常规测试，后浏览器测试”；先执行前端单测和后端集成测试，再执行桌面浏览器 E2E。
- **自动化框架**：沿用 Vitest、Maven/Testcontainers、Playwright，不新增测试框架；新增 P1 浏览器测试使用 Page Object。
- **测试环境**：前端 `http://localhost:5173`，API `http://127.0.0.1:8080`，Docker Compose 的 API/worker/PostgreSQL，Chrome channel，视口 1280×720，Planner 账号。

## 4. 执行策略

1. 常规门禁：`npm run test:run`、`mvn -q verify`、`git diff --check`。
2. 浏览器主链：`npm run e2e`，失败按环境、测试资产、契约、源码、数据前置和不稳定性分流。
3. P1 闭环：单独跑 `product-loop.spec.ts`，写入的问题和复盘数据在测试结束时恢复原状态。
4. 浏览器创建失败不归因产品；必须在资源稳定后单独重跑同一用例，并在报告记录首次批次与复跑结果。

## 5. 退出条件

- P0 自动化可执行用例全部通过，或每个失败均有明确非产品分流结论。
- P1 闭环用例通过，新增缺陷有复验结果。
- 前端单测、后端验证、构建、健康检查均有 E3 证据。
- 未覆盖的真实学校 UAT、移动端、生产发布和性能专项必须在报告中明确列出。
