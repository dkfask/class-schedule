# Bug 条目 — 2026-09-09

## BUG-20260909-001：复盘页面旧异步响应覆盖未提交输入

- **严重程度**：S1
- **状态**：已验证关闭
- **发现方式**：Playwright E2E + 最小网络复现
- **复现步骤**：
  1. 以 Planner 登录本地环境。
  2. 进入 `/retrospective`，等待当前学期复盘数据出现。
  3. 在“学校反馈”输入新内容，并在第二个复盘 GET 返回前观察字段。
  4. 等待页面异步请求完成。
- **预期行为**：用户输入未提交前不应被旧的异步读取结果覆盖。依据：产品设计 §5.1、`TC-R-01`。
- **实际行为**：首次读取返回后字段可输入，但第二个同学期读取返回后字段恢复为旧值；用户继续保存可能保存错误内容。
- **证据**：`复盘竞态复现记录_2026-09-09.md`（E3）；两次 `GET /api/retrospectives?termCode=2026-FALL` 均 200；PATCH 保存接口可正常接收并返回字段。
- **环境**：`http://localhost:5173` / Planner / Chrome channel / 1280×720。
- **根因分析**：**Verified**。`RetrospectiveView.vue:17-39` 的 `load()` 会被 `onMounted` 和学期选择 `watch` 同时触发；两个异步请求都直接写入 `data.value` 和 `form.value`，且任一请求的 `finally` 都能结束公共 `loading`。旧响应因此覆盖用户表单。修复后通过 `loadSequence` 和 `termCode` 快照，仅最新且仍对应当前学期的响应允许回写，见当前文件 `:17-42`。
- **影响范围**：
  - 功能面：复盘备注的初次加载、刷新和切换学期时的异步读取；同类风险需要继续关注其他带学期 watch 的页面。
  - 数据面：修复前未必产生数据库脏数据，但会造成用户误保存旧值；本轮测试产生的临时复盘值已恢复。
  - 用户面：Planner 在实施复盘时受影响，Reviewer/业务负责人当前为只读，不走该写入表单。
  - 安全面：不构成越权或敏感数据暴露。
  - 修复波及面：仅前端复盘加载状态、当前学期快照和表单回写；保存接口、数据库、其他路由未改动。
- **Severity 依据**：未造成已确认的数据持久化丢失或越权，属于核心 P1 交付记录的部分降级和误保存风险，按影响业务数据输入的 S1 处理。
- **修复建议**：已完成最小修复：异步读取增加序号和学期快照，旧响应不能覆盖当前页面状态；保留接口契约不变。
- **回归建议**：`TC-R-01`、`TC-P1-04`；关联回归为 P1 页面路由加载、学期切换和复盘 Controller 集成测试。
- **复验轮次**：1，组件单测和浏览器 E2E 均通过，状态更新为已验证关闭。
